What changed in the send flow

With the switch off, nothing changed: the flow in the first flows guide is exactly what runs. With it on, four steps are inserted between "load context" and "call the provider":

  1. Count documents. Zero means retrieval is skipped entirely, and the embedding model isn't even loaded.
  2. Embed the newest question and score every stored chunk.
  3. Filter by the relevance threshold, keeping at most 4 passages.
  4. Build the prompt with a delimited <sources> block, and send the sources as the first stream frame.

Chunking lab

This runs the same algorithm as services/chunking.py (checked against the Python on 245 inputs). Change the text and the two settings and watch where the cuts fall. The shaded text at the start of a chunk is the overlap copied from the end of the previous one.

ProseShort paragraphsNo punctuation App defaults (800 / 100)

Why it's built this way

  • Paragraphs first. A paragraph break is a natural boundary, so short paragraphs are packed together.
  • Sentences next. A paragraph longer than the limit is cut between sentences, never inside one when avoidable.
  • Spaces last. Text with no punctuation is cut at a space; with no spaces at all, at the limit.

The bug this lab shows

An early version made no overlap at all inside long paragraphs: the pieces already filled the limit, so there was no room to prepend the shared text. Now long paragraphs are cut overlap + 1 characters short to leave room. Set overlap to 0 and back to see chunks change size.

Trade-offs to feel

  • Big chunks: few, vague vectors; more tokens per answer.
  • Small chunks: precise, but each loses its surrounding context.
  • Overlap: protects ideas on a boundary, costs storage and near-duplicate results.

Search and the relevance threshold

Search scores every stored chunk and returns the best k, even if all of them are poor. The threshold is what decides which of those are allowed into the prompt. Try the lab, then step through the real request.

Lab: score the chunks, then apply a threshold

Same word-matching embedder as the offline backend mode. One chunk per line; edit freely.

cats sleepjupiter moons feline sleep habitsquantum computing
Cap: 4 passages (MAX_PASSAGES)

Two things to notice with "feline sleep habits".
  1. It means the same as "how much do cats sleep", but shares no words with the cat chunk, so this embedder scores that chunk 0.000. A real embedding model maps both to nearby vectors, which is the whole reason to use one.
  2. Yet an unrelated chunk (kittens, or dogs) scores about 0.2. That is a hash collision: this toy embedder drops every word into one of only 384 buckets, and sometimes unrelated words land in the same bucket. It is a known weakness of the "hashing trick", and the offline backend mode behaves identically. A real model fails differently, but no retrieval is perfect: that is why thresholds and the Test search panel exist.
The threshold mechanics you see here are identical for any embedder.

Why scores need a per-model threshold

A cosine score is a similarity, not a probability, and each model spreads its scores differently. The app's default (0.5 for bge-small) is a starting guess, not a measurement. Expand a citation to see its score, ask one question the documents clearly answer and one they clearly don't, then set RAG_MIN_SCORE between the two.

Why unit vectors

Every vector is scaled to length 1 when stored, so cosine similarity needs no division: scoring all chunks is one matrix-by-vector multiply. That's the matrix @ query in the flow above.

Scale

This is an exact brute-force scan: fine for thousands of chunks. Beyond that you'd swap in an index (pgvector, sqlite-vec) behind the same function.

Where untrusted text goes
Retrieved passages come from files the user uploaded, so they may contain instructions aimed at the model. They go in the user turn, inside delimiters, and the system message (our own text) tells the model to treat them as reference material only.

    
Why tags are escaped
If a passage contains </sources>, it could "close" the block early and make what follows look like it came from the user or the app. Every <sources> or </sources> inside a passage (any case, any spacing) is turned into &lt;…&gt;. The check line above counts closing tags: it must be exactly 1.

    
What this does NOT prove
Escaping stops one specific trick. It can't stop a model from being persuaded by text it reads. That's why the app also gives the model no tools or secrets, and why the README says injection is reduced, not eliminated.

  







  
Citations: stored, restored, and why they're a snapshot

  
An answer's evidence is saved with it, so it can be shown again after a refresh, a retry, or even after the source document is deleted.

  

    

    
    

  

  

  

  

    
Why a snapshot
A reference could dangle or point at changed text if the document is edited, re-chunked or deleted. The copy always shows what the answer actually relied on.

    
Why a new table
Adding a column to messages would need an ALTER TABLE on existing databases, which create_all never does. A new table is created automatically, so your saved chats kept working.

    
The privacy catch
Deleting a document does not remove its text from old citations. Only deleting the conversation does. Worth knowing before storing sensitive files.
