For the current, step-by-step flows open AI-Chat-Flows-Guide.html (streaming, saved chats) and AI-Chat-RAG-Flows-Guide.html (documents and RAG).

How the app is built

A React chat UI talks to a FastAPI backend, which validates the input and calls an AI model. The browser never sees the API key.

System architecture

Key idea: the frontend never calls the AI directly. The key and the rules live on the server.

Frontend

React components render state. App.tsx owns the state; chatService.ts owns the network call.

Backend

main.py handles HTTP. schemas.py defines the rules. openai_service.py talks to the model.

Contract

One request shape and one response shape connect the two. Changing one means changing the other.

Backend: FastAPI and Pydantic

Python concepts explained against the JavaScript you already know.

Decorators

@app.post("/chat") registers a function as a route, like app.post('/chat', handler) in Express.

Type hints drive behavior

The parameter request: ChatRequest makes FastAPI parse JSON, validate it, and return 422 on failure. The handler only runs on valid data.

def vs async def

The OpenAI call is synchronous, so a plain def runs in a thread pool and doesn't block other requests.

Environment variables

load_dotenv() reads backend/.env. os.getenv() returns None when a variable is missing.

Validation rules

Error mapping

CauseHTTPWhat the user sees
Bad request body422Validation message (never reaches the AI)
Provider timeout504"The AI took too long…"
Can't reach provider502"Could not reach the AI service…"
Rate limited429"Too many requests…"
Bad key or missing config500"The server is not configured correctly."
Empty model reply502"The AI returned an empty response."

Details go to the server log. The browser gets a safe message, so internal details and secrets never leak.

Frontend: React and TypeScript

Small components, one owner of state, and a typed service layer.

Why the new array is built first

setMessages is asynchronous. Reading messages after calling it returns the old value, so the code builds history before the await.

Enter vs Shift+Enter

onKeyDown calls preventDefault() on a plain Enter and sends. Shift+Enter falls through and inserts a newline.

Retry without duplicates

The user message stays in state after a failure, so Retry re-sends the same history instead of adding a new message.

fetch doesn't reject on 4xx/5xx

Only network failures reject. The code checks response.ok and reads FastAPI's detail field.

CORS and security

Browsers enforce CORS. curl and Swagger ignore it, which is why the same endpoint can work in one and fail in the other.

Allow only known origins

allow_origins=["*"] lets any website call your API from a visitor's browser. Use an exact list.

Secrets

Only the backend reads OPENAI_API_KEY. Vite exposes only variables prefixed with VITE_, and those are public.

Validation is the real boundary

Frontend limits help honest users. Anyone can bypass them, so the Pydantic rules are what protect your cost.
