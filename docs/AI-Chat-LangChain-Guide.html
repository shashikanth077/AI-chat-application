AI Chat App: LangChain

LangChain in this app: what moved, and what deliberately didn't

Phase 15 puts the model call, the document search and a new follow-up-question step on LangChain. The rule was: change the plumbing, keep the contract. The stream frames, ChatServiceError, the SQLite tables, citations and idempotent retry behave exactly as before, so the React app needed no changes.

The LCEL chain: from your message to streamed text

LCEL ("LangChain Expression Language") joins steps with |. Each step takes the previous step's output. Here: a prompt that arranges the messages, a chat model that calls the provider, and a parser that turns model chunks into plain strings.

The whole thing

_PROMPT = ChatPromptTemplate.from_messages([("system", "{system}"), MessagesPlaceholder("history")])

chain = _PROMPT | get_chat_model() | StrOutputParser()
chain.stream({"system": system_text, "history": [HumanMessage(...), AIMessage(...)]})
  • The system text is a variable, not part of the template, and the history is already message objects. LangChain never parses braces in what the user typed (a test sends {system} {history} and checks it arrives verbatim).
  • ChatOpenAI with base_url works with any OpenAI-compatible provider, so Groq keeps working: OPENAI_BASE_URL=https://api.groq.com/openai/v1.
  • Same limits as before: 30 s timeout, 2 retries, max_tokens=800 (sent to the provider as max_completion_tokens).

The document store as a LangChain retriever

A retriever is anything with .invoke(query) -> list[Document]. SqliteRetriever wraps the existing search; no storage or scoring code changed. The payoff is a standard interface: a vector-store retriever, a hybrid one, or a re-ranking wrapper could replace it without touching callers.

Follow-up questions: rewrite before you search

"And how long do they nap?" is a fine question in a conversation and a useless search query: the vector has no idea what "they" is. A small chain turns it into "how much do cats sleep" using the recent messages, for searching only. The model still receives your real message.

Rules that keep it safe and cheap

  • Skipped when there is only one message, when "Use my documents" is off, and when there are no documents. No extra call in those cases.
  • Never blocks an answer. Any failure (network, rate limit, odd output), an empty result or one over 500 characters falls back to your original question.
  • Cheap: it sees the last 6 messages, each cut to 600 characters, and may answer in at most 120 tokens.
  • Search only. The rewritten text is embedded and thrown away: it is not stored, not shown, and not sent to the answering model.
  • Costs one extra model call per follow-up. Turn it off with RAG_REWRITE_QUERIES=false.

How it is tested without a network

The fake sits at the bottom: a real ChatOpenAI and the real chain run, and only the OpenAI SDK's HTTP-calling chat.completions resource is replaced. That keeps almost every older test valid, and the tests exercise the actual LangChain code.

Decisions, trade-offs and what was not adopted

Honest framing

Nothing in this app needed LangChain. The hand-written version was small and fully tested. What the migration buys: a standard model and retriever interface (swap providers or stores in one place), a place to grow (more chains, agents), and one real feature, the follow-up rewrite. What it costs: dependencies, and an API that moves between versions.

Deliberate non-adoptions

LangChain offersNot used because
RecursiveCharacterTextSplitterThe existing chunker is sentence-aware, fully tested, and mirrored in TypeScript for the demo with a parity test against the Python output. Swapping it would break that parity for no gain.
PyPDFLoader and other loadersThey read from a file path (and live in the heavy langchain-community package). Uploads are processed in memory and never written to disk, which is a documented security property. pypdf already does the job.
Vector stores (Chroma, FAISS)The SQLite store holds the citation snapshots and per-model vectors the app relies on, and brute force is exact. A retriever wrapper gives the same interface.
LangGraphThe flow is linear (rewrite, retrieve, answer). A graph would add structure without adding behaviour; revisit when there are tools or branching.
LangSmith tracingTracing sends prompts and replies to a third party, which conflicts with "message text is never logged". If added, it must be opt-in and off by default.

Things to watch

  • Versions. langchain-core and langchain-openai are pinned only by minimum version. Pin exact versions (a lock file) before deploying.
  • Rewrite quality is unmeasured. It is tested with a scripted model, so tests prove the plumbing and the fallbacks, not how well a real model rewrites. Check it on your own conversations.
  • Rate limits. A follow-up with documents makes two provider calls. On a tight free tier, turn the rewrite off.
  • Priming the stream. open_reply_stream now waits for the first piece of text before returning, so any pre-token failure is an HTTP error. (A failing first chunk used to become an in-stream error event.)
